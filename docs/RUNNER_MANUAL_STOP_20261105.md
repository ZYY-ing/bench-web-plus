# 手动停止旧容器后重新部署（2026-11-05）

本版本撤下“释放并替换旧 Runner”选项，不自动停止旧 Runner 或旧容器。

## 两种流程

1. 复用旧安装：管理员先手动停止或删除专用旧 Runner 容器，再选择新容器，沿用原 Runner 端口、受限 TLS 端口、容器内项目路径和实际宿主机挂载目录。中心自动识别旧登记，远端再次核对 Docker 已停止/删除且端口没有 LISTEN，备份配置和程序后安装，成功后原条目切换到新容器。旧容器仍在运行时明确拒绝，不尝试停止它。
2. 并存新增：保留旧容器运行，为新 Runner 配置独立的 Runner/TLS 端口、项目路径和实际宿主机目录；成功后列表保留旧条目并新增一个同 IP 的容器条目。不同容器路径指向同一宿主目录仍会拒绝。

专用 Runner 容器可以手动停止；带有 vLLM 或他人服务的共享容器不能据此随意停止。安装路径可复用不代表任意镜像都可保证安装成功：Python、AISBench 依赖、RW 挂载与包源/离线依赖仍须满足要求。

## 回退与环境隔离

- 旧容器保持停止，不在回退时自动启动。
- 新安装异常时，回退旧程序、Runner 配置及令牌；不删除结果或改写旧依赖。
- 如果新 Runner 已启动，回退前只停止通过身份和空闲状态核验的新 Runner 进程。端口身份未知或存在活跃任务时拒绝覆盖文件。
- 通过 `/proc/net/tcp*` 的 LISTEN 状态确认监听，忽略已建立和 TIME_WAIT 连接；进程在检查期间退出时，等待端口稳定释放后继续回退，不再要求已退出的新 Runner 提供 HTTP 状态。
- 新虚拟环境和可编辑 AISBench 源码按完整容器 ID 分目录；跨镜像失效的 Python 链接通过实际 `ais_bench --help` 检出，不复制旧虚拟环境。
- TLS 组件启动改为最长 10 秒轮询，验证新进程 PID、目录、命令和监听 socket 后才返回成功；不能只等 1 秒就根据 PID 文件判定失败。

## 更新正在运行的中心

工作区代码与运行在 ProgramData 的中心是两个副本。当前进程无管理员权限，更新受保护副本需在管理员 PowerShell 中执行；更新保留 ProgramData 中的实时账号、机器清单和 SSH 授权：

```powershell
cd D:\aisbench_web\bench-web-plus
$fleetPython = 'C:\Users\example-user\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $fleetPython -X utf8 -m fleet.service stop --boot
& $fleetPython -X utf8 -m fleet.service install-boot
```
