# Bench Web Plus 脱敏交接（2026-11-04）

本文件记录本次会话形成的代码、操作边界、实测结论和后续事项。服务器地址、用户名、个人路径、指纹、凭据、容器实例 ID、数据库和原始运维日志均不随仓库交付。文中的路径和地址只用 README 中的通用示例。

## 需求与交付范围

在原 ascend-bench-web 评测页面上增加轻量本机中心：管理员统一连接服务器并安装 / 接回多机 Runner，用户在原精度、性能流程前选择空闲 Runner。保留原 AISBench 安装方式和测试记录 / 导出行为，减少本机依赖与手工命令，不下载模型权重，不代替用户启动 vLLM。

推荐部署方式只有一条：电脑运行本机中心，管理员网页完成 SSH 连接与 Runner 部署，用户打开同一中心的用户入口。原独立 Runner 模式只作为回溯与调试兼容，不是新版推荐流程。

## 已实现

- Python 标准库 HTTP 中心；SSH 依赖 Paramiko 固定版本，安装在工具目录，不读个人私钥、SSH 配置或 ssh-agent。服务器密码仅用于内存会话，不写配置 / 日志 / 数据库，主机公钥指纹固定校验。
- 管理员与用户入口及会话权限分离，管理接口须凭据、CSRF、同源校验；用户会话不能连接机器、部署或移除 Runner。
- 连接与部署是同一向导；已有容器 / 本地镜像新容器两种方案。容器不禁选，按已安装运行、已安装停止、已安装且容器退出、未安装（运行优先）排序。部署时再验证权限、网络、挂载、目录和端口。
- 已选停止容器自动启动，执行原启动命令；新建容器不启用 privileged、不挂 NPU、不自动拉镜像。
- 全部 scripts / website 文件 SHA256 清单判断版本；最新版直接启动 / 复用，旧版仅身份核实且空闲、确认无测试进程后升级。复用已存在且可执行的 AISBench；缺少时沿用安装脚本补齐依赖。
- 安装包缓存按 SHA256 检查，命中上传 0 B，否则显示上传字节、比例、速率，上传完成再校验。当前固定工具包即目标版本，不自动追踪 GitHub main。
- 网页可填写服务器安装代理、pip 源和可选域名映射；代理 / 源不接受嵌入的账号密码或查询令牌。可选 hosts 映射只针对所选容器并在界面注明。
- 部署成功六步均显示绿色对勾；失败保留具体错误。网页托管模式不再输出旧版“用户手工建 SSH 隧道、输入 Runner token”的操作指引；独立模式仍保留自身步骤。
- 管理卡明确区分 SSH 管理通道与 Runner 服务状态。退出或认证失效后隐藏管理按钮、关闭弹窗、取消部署轮询、清空页面中的管理状态。
- 删除测试环境只是删除接入记录，保留容器、项目、进程、结果；有任务或待核对占用则拒绝。晚到的刷新不能把已删除记录写回。
- 用户列表与管理员当前 Runner 列表使用同一数据源；部署历史不参与补全，已删除环境不重现。页面重新获得焦点时只同步本地接入清单，不后台 SSH 扫描服务器。
- 仍登记但不可用的节点保留显示且不可选择；全部不可用时直接显示清单。精度 / 性能页须先刷新并确认健康空闲节点，后续表单才可用，后端也验证；测试记录页没有选择 Runner 步骤。
- 列表包含容器名，忙碌节点包含当前目标 IP:port 与 model_name。只向用户暴露必要状态，不暴露服务器凭据或内部运维配置。

## 两个实际故障与修复

### 退出后误报端口占用

旧空闲 Runner 正常退出后，安装前探测仍因 TIME_WAIT 拒绝绑定。端口探测加入 SO_REUSEADDR，允许这种正常地址复用，继续原端口，不设置 SO_REUSEPORT，不自动换端口，也不停止未知监听进程。真正服务占用仍拒绝操作。

### 换容器复用目录但身份不匹配

持久化目录中旧 runner-config.json 的容器名覆盖了新启动环境。现在 ASCEND_BENCH_CONTAINER 优先，保留其他服务配置、路径、结果。若旧进程已运行并返回旧名，迁移前必须验证所选容器内 PID、命令、工作目录、启动环境和实际监听 socket 所有者，且空闲并确认无测试进程。身份不明时不绕过校验、不杀进程。

同机 host 网络容器共用端口，不同 Runner 并行运行应选择独立端口和独立持久化目录。复用一个目录用于替换原容器，不等于多个 Runner 可以同时写这个目录。

## 已知限制

1. 只监听 127.0.0.1；没有多人共享 HTTPS 中心、普通用户账号或结果隔离。其他电脑要独立运行中心，不能直接填写管理员电脑 IP 访问。
2. 独立中心间的接入清单和中心目标锁不共享，不能当作全局调度器；远端同一 Runner 的锁仍有效。外部绕过本工具的测试 / vLLM 资源占用不检测。
3. 任务结果未知不按 TTL 自动释放占用；必须核对原请求与进程，不能为提高可用性盲目清锁。
4. 服务器首次缺少 AISBench 且不可访问依赖源 / 离线依赖时安装会失败；源码包不含完整 wheelhouse、容器镜像和模型。虚拟环境不可跨系统 / CPU / Python ABI 直接搬用。
5. 退出中心后 SSH 会话消失，需重新认证。发布包无本机凭据、服务器档案、运行数据，下载后是全新环境。
6. Python 对密码清除引用不保证物理内存擦除；可信管理员电脑和受保护专用账号仍是使用前提。

## 接手后的工作原则

先核对当前实际容器、端口、目录和任务，历史记录不能当实时状态。只操作管理员明确选择的专用目录与容器，不修改模型、驱动、宿主系统配置或其他项目；停止服务先核实归属，不全局 pkill。用户明确删除的环境不自动恢复。网络异常可能留下已启动的远端任务，先核对再重试。

建议后续先用 README 在另一台干净电脑做安装验收，再在授权服务器验证外网 / 内网 / 预装 AISBench 三种路径。若要共享中心，单独设计认证、HTTPS、权限隔离和统一锁；不要直接暴露当前本机端口。
