# 共享中心 v0.2.0-preview.1：实现与验收交接

本文件脱敏，不包含实际机器地址、个人目录、用户名、密码、指纹、证书私钥或原始运行数据库。共享中心先在本地实现和验证；用户随后授权将源码、说明和安装包发布到本仓库，以便换电脑部署。

## 已实现

- 一个中心运行在选定个人电脑；默认网址进入用户页，普通用户免登录。管理员从同一页面进入登录，用独立账号和密码管理，可跳转用户页。
- 多管理员添加、停用、启用、密码重置；加盐 scrypt 校验值、登录版本撤销和操作记录。保留至少一个可用管理员，并发停用也不能锁死全部账号。
- 首次本机初始凭据在正式管理员创建后失效；共享模式必须先创建账号，演示模式不能对外开放。
- HTTPS、明确 Host/Origin 校验、Secure/HttpOnly/SameSite Cookie、用户网段限制、请求大小与并发保护。没有20人硬上限，不挤掉其他正常用户会话。
- 中心后台配置和 Windows 当前用户登录后启动任务；不保存 Windows 密码，不提权、不自动修改防火墙、信任库、电源或机器级系统服务。
- 保留原有密码 SSH 部署，增加项目内受限 TLS 评测连接。日常查询不需要管理员保持 SSH 会话，不读取个人 SSH 私钥，不修改 SSH 授权文件。
- 中心持久化工具专用凭据和证书信任，可在重启后查询已接入 Runner。证书/连接异常时，通过重新登录 SSH 核实状态与进程归属后恢复，不抢占未知端口或停止未知进程。
- 管理员清单与用户清单使用同一数据源，删除记录不会被晚到刷新复活或被失败历史补回。无 Runner 时用户仍可直接进入空页面。
- 用户刷新与选择门禁、短时间合并状态查询、任务占用锁；普通用户不能停止其他用户任务，管理员可接管。
- 匿名用户任务归属可跨中心重启保留，旧选择和刷新状态清除；浏览器 Cookie 或会话失效后需要管理员接管旧任务。

## 自验证记录

1. 本地后端回归已覆盖50项：原34项和新增共享中心、账号、TLS、会话恢复、并发、来源网段及服务定义检查；前端无依赖脚本检查刷新门禁、不可用清单及删除同步。
2. 两台实际服务器均由管理员网页后端流程部署、更新并接入受限 TLS 连接；第二台命中安装包缓存、上传0 B。已复用原 AISBench，没有为本次共享功能新增大型服务器依赖。
3. 中心实际重启后，在管理员尚未登录、SSH 会话数为0时，用户可以刷新、选择两台 Runner，并读取真实历史记录。
4. 20个独立用户会话并发进入、刷新和选择均通过。这是功能并发检查，不作为无限容量或稳定延迟保证。
5. 对未知/错误来源、错误证书、错误接入凭据、普通用户管理接口调用、跨用户停止请求均有拒绝检查。管理员停用、重新启用和密码重置不能使旧登录恢复。
6. 曾用项目内受控回放接口检查请求与占用保护；任务没有生成可核验的评分，已记为失败，不算模型测试结果。按用户最新要求停止继续模型/精度验证，临时接口已关闭、端口释放，Runner 原配置已恢复。

## 验收边界

- 用户明确要求本轮先完成管理员/用户管理 Runner，真实 vLLM 精度和性能验收不在本轮完成范围。保留原评测逻辑，没有用模拟结果代替真实模型测试。
- 已做中心到两台服务器的真实 TLS 接入，以及本地多浏览器会话/HTTP权限验证；另一台个人电脑的浏览器互访、公司证书与 Windows 防火墙仍需在正式中心网络确认。
- 用户实际首次配置中已创建当前用户后台任务；修复 Windows XML 编码与 SID/账号名称标准化问题后，任务实际运行、监听共享端口，HTTPS 页面及用户接口返回200。新电脑的任务权限仍须实机确认。
- 自动常驻为当前用户登录 Windows 后运行，锁屏可以继续。注销、关机、休眠、断网会影响中心；无人登录也需运行的场景需受管系统服务，不通过保存 Windows 密码实现。
- 服务器/容器重启后原 Runner 或受限组件可能停止，管理员按需重新部署恢复。中心重启与服务器重启不是同一个事件。
- 普通用户匿名、记录仍共享，不提供个人结果隐私隔离。工具锁不覆盖绕过本工具的服务与测试进程。
- 删除接入记录不是卸载或远端授权文件销毁。工具专用 API 凭据及中心 CA 私钥必须保存在受保护的中心数据目录。

## 首次部署反馈及修复（2026-11-04）

1. Windows 的 python 命令可能仅为商店占位入口，旧脚本直接显示按任意键退出。启动器现在通过真实解释器输出检查 Python 版本，支持 FLEET_PYTHON 完整路径；补充 Python 官网安装、PATH 和 pip 验证步骤。
2. getpass 不显示字符或星号；两次密码不同或太短时，原向导抛错退出。现在明确提示不回显，并原地重输密码，保持前面网络输入；常见输入错误和子进程失败给简洁提示。已有账号改密码需用 fleet.admin reset，不通过重新运行安装器重建账号。
3. schtasks 查询的 XML 声明为UTF-16，但管道输出实际使用控制台编码。现在区分真正UTF-16字节、UTF-8 BOM和Windows控制台编码后解析，保留归属检查。
4. Windows 可能把任务主体SID转换为电脑名/用户名。现在通过系统把账号解析回SID再比较；仍检查当前用户、工作目录和参数，不覆盖其他安装任务。
5. Python 3.14 默认严格TLS检查揭示测试证书缺少AKI等字段。新CA及服务证书补充SKI/AKI、KeyUsage和服务端EKU。当前首次安装的证书已备份修复，CA私钥保留，并实际通过严格TLS及主机名验证。旧预览生成的CA不自动迁移；已有旧CA的中心需备份后显式修复/重新初始化，重新分发公钥证书，不能通过关闭校验绕过。
6. 当前电脑使用Python 3.14与该解释器匹配的项目依赖完整运行50项测试通过。旧开发目录中另一Python版本的cffi扩展不能直接给3.14使用；不跨Python ABI拷贝 .fleet-deps。
7. 选择已有容器却保留示例安装目录时，持久化RW挂载检查会正确拒绝。应依据 docker inspect 选择该容器现有挂载内的专用子目录，不能盲用示例路径或关闭检查。本次失败记录的工具包已上传并校验，但Runner安装尚未执行；后续独立SSH复核凭据被拒，不宣称该重试已成功。

换电脑检查清单、端口关系、重置/从头部署及错误处理详见 [中心部署排障](CENTER_TROUBLESHOOTING.md)。跨电脑浏览器互访及新电脑防火墙仍待实际验收。不要把测试数据库、临时账号、服务器日志或私有凭据放入安装包和仓库。
