# 共享中心部署详细说明（当前源码）

> 新部署下载当前 main 源码，操作总入口见[README](../README.md)，实现与验证边界见[当前交接](HANDOFF.md)，其他文档见[索引](README.md)。

本文地址和路径仅为占位示例，真实连接信息只保存在本地配置。公开发布边界见 [SECURITY.md](../SECURITY.md)。


中心安装在一台常开个人电脑上。普通用户免登录打开统一网址；管理员使用各自账号登录管理页。关闭管理员网页或退出管理员不会关闭中心和 Runner 连接。

先下载当前 main 源码 ZIP 并解压到新目录；历史 Release 不含全部后续修复。[首次部署排障与从头配置](CENTER_TROUBLESHOOTING.md)汇总 Python、密码、后台任务、证书、网段和容器挂载问题。

## 安装要求

| 位置 | 需要安装 |
|---|---|
| 中心电脑 | Python 3.12+（含 pip）和共享中心工具包 |
| 其他管理员电脑 | 仅现代浏览器，不需要第二套中心、Python、SSH 或 Docker |
| 普通用户电脑 | 仅现代浏览器，不需要管理员密码、服务器密码或测试环境 |
| 测试服务器 | 已有 SSH、Docker、Python 3、host 网络测试容器和专用持久化目录；模型服务另行准备 |

无需 Node.js、前端构建或外部数据库服务。SSH 组件仍安装在工具目录 `.fleet-deps`，不修改系统 Python。不下载模型权重，不自动启动 vLLM。

## 中心电脑首次配置

### 先安装 Python（Windows，只在中心电脑安装）

1. 打开官方 Windows 下载页：https://www.python.org/downloads/windows/ 。选择 Python 3.13 的正式版本，点击该版本下面的 **Download Windows installer (64-bit)**。常规 Intel/AMD Windows 电脑使用此安装包，不要选择 embeddable package、源码包或预发布版。
2. 双击下载的安装程序，在首页勾选 **Add python.exe to PATH**，再点击 **Install Now**。保留默认的 pip 组件即可，通常安装到当前用户，不必安装给所有用户。
3. 安装完成点击 Close，关闭之前打开的命令窗口。
4. 按 Win+R，输入 cmd 并回车，分别执行 `python --version` 和 `python -m pip --version`。应显示 Python 3.12 或更高版本及 pip 版本；如果跳转商店、没有输出或找不到命令，说明还没配置好，先不要继续中心安装。
5. 关闭验证窗口，双击工具目录里的 `setup-shared-center.cmd`。

中心电脑无法访问外网时，可在另一台联网电脑下载上述官方 Windows 安装程序，复制到中心电脑后安装；后续 SSH 依赖离线准备见本文“外网、内网与离线安装”。其他管理员和普通用户只用浏览器，无需安装 Python。

### 再配置中心

1. 解压当前 main 源码 ZIP 到本人有写权限的独立目录，安装 Python 3.12+。
2. Windows 双击 **`setup-shared-center.cmd`**。
3. 填中心固定 HTTPS 地址、允许访问的用户网段、首个管理员账号和密码。
4. 选择已有公司可信证书，或者生成本中心测试证书。
5. 安装器为当前 Windows 用户建立登录后启动的后台任务，并启动中心。

地址示例 `https://192.0.2.10:19881`；网段按实际网络填写，如 `192.0.2.0/24`。多个允许网段用逗号分隔。地址和网段由管理员明确填写，程序不自动扫描本机网络，不自动修改防火墙、电源设置或系统证书信任库。

请确认中心电脑不休眠、不断网，并只向需要使用的内网开放中心端口。共享模式必须使用 HTTPS、明确允许网段并已有管理员账号；不接受直接向全部互联网开放匿名用户入口。

### 证书与用户电脑

有公司认可的可信证书时，用户直接打开网址，无需安装任何运行环境。使用测试证书时，用户首次需要信任 `.fleet-data/tls/ca.pem` 这个公钥证书；不要跳过浏览器证书警告。

**不能分发** `ca-key.pem`、`server-key.pem`、`channels.json` 或整个 `.fleet-data`。这些只留在中心电脑，并限制备份访问权限。

### 后台运行条件

后台任务使用当前用户身份和最低权限，不保存 Windows 登录密码。Windows 用户登录后自动运行，锁屏可以继续；注销、关机、休眠或断网会影响中心。

需要无人登录 Windows 也运行时，正常停止当前中心，再右键以管理员身份运行 `install-center-autostart.cmd`，完成一次性开机任务安装。安装器将程序、Python 和中心数据复制到受保护的 `ProgramData/BenchWebPlus`，由 SYSTEM 开机运行；不保存 Windows 密码，不配置自动登录。之后使用受保护目录中的中心，原工作区副本不再作为运行数据源。升级时先正常停止开机任务，再从原安装目录重新运行该安装器。当前用户登录任务和开机任务是两种模式，不要同时启动两个中心。

若后台任务安装权限不足，可以先双击 `start-fleet.cmd` 前台运行并保留窗口，再由有任务管理权限的管理员完成安装。不覆盖属于其他目录或用户的同名任务。

维护命令，在中心目录执行：

```powershell
python -m fleet.service status
python -m fleet.service start
python -m fleet.service stop
python -m fleet.service remove
```

`remove` 仅移除本工具后台启动任务，不删除项目、账号、Runner 或结果。日志为 `.fleet-data/center.log`，过大的旧日志保留一份轮换备份。

## 管理员部署和维护 Runner

1. 打开中心网址，点击“管理员登录”，用独立账号和密码进入管理页。
2. 点击“部署 Runner”，填写服务器 SSH 信息和本次密码，核对公钥指纹；保持“首次授权后自动管理”勾选，注册工具专用密钥。旧机器需要重新登录授权一次，已有接入不会自动获得 SSH 权限。
3. 选择已有容器或已有本地镜像，填写专用项目目录、Runner 端口（默认18787）和受限连接端口（默认19787）。
4. 保持“启用受限持久连接”勾选；按网络需要填写安装代理和 pip 源，提交部署。
5. 相同安装包复用缓存、上传0 B；否则自动上传并校验。检查源码版本并复用可执行 AISBench，只有身份核实、空闲且无测试进程的旧 Runner 才会更新。
6. 全部步骤绿色对勾表示部署接入成功。管理员可以退出网页，用户日常访问不依赖管理员登录。

选中停止容器后会执行其原有启动命令。新建容器只使用服务器已有镜像，不挂 NPU、不使用 privileged、不启动 vLLM。目录、端口和其他服务不能盲目覆盖。

### 持久连接

切换容器或镜像后，旧项目虚拟环境的 Python 链接可能失效。部署复用 AISBench 前会实际执行 `--help`；新建依赖环境放在 `environments/<完整容器ID>/bench-venv`，可编辑 AISBench 源码放在同一容器 ID 下的 `benchmark`，避免容器 B 修复自己的依赖时改写容器 A 的环境。不会继承其他容器的项目虚拟环境路径，可复用新容器中实际可运行的系统 AISBench。连接检查会明确提示失效的启动解释器。

Runner 与 AISBench HTTP 评测进程均设置 `TORCH_DEVICE_BACKEND_AUTOLOAD=0`，性能数据生成只在 CPU 上加载 tokenizer，不自动初始化 NPU 后端。部署同时验证 Runner Python 能导入 `AutoTokenizer`；失败任务的执行日志保留完整异常链，便于定位被 transformers 包装的底层导入错误。

首次授权使用本次密码 SSH；后续部署、维护和断线恢复使用工具专用密钥。部署后在选定项目目录下增加 `center-access/<连接ID>/`，启动只接受受限评测 API 的 TLS 连接组件。

日常链路：用户浏览器 → 中心 → 服务器受限 TLS API → 本机回环 Runner。

- 不保存服务器 SSH 密码，不读取个人 SSH 私钥或 ssh-agent；首次自动管理授权只增加带本工具标记的 `authorized_keys` 条目，不修改 sshd 配置或其他授权条目。
- 自动管理私钥和独立脚本签名私钥通过 Windows DPAPI 加密，文件权限限于当前用户与 SYSTEM；只允许登记的中心来源 IP、固定主机指纹及签名脚本。该通道可以执行有权限的部署维护操作，仍须保护中心电脑与管理员账号，不能视为无特权凭据。管理员可撤销授权，已连接会话也会被拒绝执行。
- TLS 组件仅提供评测 API，没有远程命令、安装、Docker 管理或任意文件读写接口；其 API 凭据与证书留在中心受保护数据目录。
- 中心需能访问服务器受限连接端口；未知端口占用会报错，不抢占、不自动换端口。
- SSH 断线后自动退避重连，间隔 2–60 秒；网络恢复后无需重新输入密码。SSH 密钥没有“连接几天后必须重输密码”的期限。被撤销、服务器指纹变化或中心来源 IP 改变时会明确阻止连接，需要核对或重新授权，不能自动绕过认证。
- 中心重启自动读取已加密凭据恢复 SSH；服务器安装本工具独立的 systemd 恢复服务，只恢复已登记、文件哈希和容器 ID 匹配的 Runner/TLS 进程。新建工具容器使用 `unless-stopped` 策略。已停止的外部容器、未知端口和 vLLM 不会被启动或停止；外部容器必须由其所有者配置开机运行，恢复服务等待其恢复。
- 已发送但结果未知的部署命令不会因自动重连重复执行；状态恢复与重放安装命令是不同的操作。
- 连接组件证书有效期一年。管理员可重新通过已核验 SSH 部署以更新组件和证书；无法确认进程归属或 Runner 状态时不会强制停服。

删除测试环境仅移出接入清单，保留服务器进程、安装目录、连接文件和结果；它不是远端卸载或凭据销毁。新电脑下载源码不会自动继承已有接入权限。

管理员可以选择两种模式：

- 保留原 Runner，以独立 Runner 端口、受限连接端口、项目目录及宿主机挂载目录新增；列表增加一项同 IP、不同容器的 Runner。安装会核验实际挂载映射，目录别名指向同一宿主目录也会拒绝。
- 复用旧端口和项目目录：先由管理员手动停止或删除专用旧 Runner 容器，再按正常流程选择新容器部署。程序自动识别同端口、同目录的旧登记，确认旧容器完全停止、原端口无监听后备份程序和配置，安装新 Runner 并迁移 TLS 接入。安装抛错时回退文件和配置，旧容器始终保持停止，不自动启动旧容器，也不再提供“释放并替换旧 Runner”选项。

旧端口和目录可复用，不等于任意镜像都能安装成功；新容器仍须具备可运行的 Python、依赖或可访问的包源/离线依赖，以及正确 RW 挂载。不要停止带有他人服务或 vLLM 的共享容器。

同机多 Runner 适合并行测试不同服务器的服务，但 CPU、内存和网络仍共享；不要把它当作性能隔离。同一中心对同一推理服务仍有任务互斥。替换不会抢占未知服务，也不会在旧 Runner 忙碌时强行停止。

其他个人电脑通过浏览器访问同一中心并登录管理员，使用的是同一套服务器授权和清单；SSH 连接与密钥始终在中心端，浏览器电脑不需要服务器密码。在另一台电脑独立运行中心则属于另一套安装，不能自动继承 DPAPI 加密的授权。

旧容器停止或删除后遗留的测试占用，会在 SSH 确认 Docker 中原容器已删除，或容器完全停止、无宿主 PID 后自动处理；原容器仍运行或状态不明时不释放。中断的旧部署记录不阻止重新选择容器部署，新部署成功后自动接续旧记录；同一端口的远端部署有互斥锁，避免网络异常后并行执行两轮安装。持久连接的暂时失败会在当前部署内自动重试3次，整体成功后直接显示部署完成，无需额外点击核对。真实故障仍会明确显示失败，可直接重新部署；手动核对入口仅保留为可选排障工具。

### 推理服务地址与 tokenizer

Runner 可以评测其他服务器上的推理服务，不按 `service_hosts` 或 `service_ports` 限制目标。地址填写纯 IP/主机名，端口单独填写；是否可用以 Runner 发起的 HTTP 健康检查、模型列表和实际请求为准，不使用 ping 作为评测接口可用的判据。旧的受限连接组件需由管理员按“使用已有容器”重新部署更新，中心和组件两端代码均更新后才生效。

tokenizer 仍由执行 AISBench 的 Runner 本地读取。原 ascend-bench-web 也有目录存在检查和本地 AutoTokenizer 加载。网页新建 Runner 容器默认将宿主机 `/mnt` 和 `/home` 同路径只读挂载，Runner 安装目录另外单独挂载为可写，因此可直接填写宿主机这两个目录下的 tokenizer 路径，不需要复制整份权重。两个宿主目录必须存在；如果 tokenizer 位于安装目录挂载覆盖的子树内，以该专用挂载实际映射的文件为准。

已有容器不会自动追加挂载，Docker 重启也不会新增挂载；旧 Runner 需另行规划容器迁移，保留原安装目录、结果和凭据。容器内仍需具备文件读取权限。不要仅删除目录检查，否则生成测试数据和 AISBench 后续运行仍会失败。

### 多管理员账号

“管理员账号”界面支持添加、停用、启用和重置密码。当前管理员权限相同，密码只保存加盐 scrypt 校验值。操作记录只记录操作者、时间和接口，不记录请求密码。

停用、重新启用或重置密码后，旧登录不会恢复。至少保留一个可用管理员。一个管理员退出不会影响其他管理员或普通用户。

全部密码忘记时，在中心电脑本地交互维护，密码不进入命令行历史：

```powershell
python -m fleet.admin create admin2
python -m fleet.admin reset admin1
python -m fleet.admin disable admin2
python -m fleet.admin enable admin2
```

首次本机也可用 `.fleet-data/console-token` 的完整字符串进入管理页创建账号。创建首个正式管理员后，初始凭据和它的旧登录立即失效。共享模式必须先有正式管理员。

## 普通用户使用

1. 打开同一个中心网址，默认就是用户界面，不需要等待管理员先登录。
2. 未部署时显示空列表；不可用 Runner 保留并说明原因。清单与管理员当前测试环境一致，不从历史失败记录补回已删除环境。
3. 点击刷新，选择健康空闲 Runner 并确认，再按原流程配置推理服务与测试参数。忙碌条目显示测试目标和模型名。
4. 未选择 Runner 时后续步骤不可用，提交时中心和 Runner 还会校验占用。普通用户不能停止其他用户发起的任务，管理员可排障接管。
5. 测试记录保持原工作台布局。仍是 Runner 项目共享记录，没有普通用户账号或结果隐私隔离。

不设20人硬上限，不会因为第21个人进入就挤掉其他会话。后台限制同时处理的请求数量，以保护资源；这不等于限制能打开网页的人数。

管理员和普通用户点击刷新共用每个 Runner 的采集结果，不进行定时后台采集。没有有效缓存时实时查询；同一 Runner 已有查询在执行时，后续刷新等待并复用这一轮结果，不重复连接服务器。缓存窗口从采集完成后计算，缓存命中不会延长窗口。

中心记录每个 Runner 最近20次成功采集的平均耗时（不含排队和缓存读取），以 `n = ceil(平均耗时 × 2)` 秒确定复用窗口，最短1秒、最长10秒；无成功样本时暂用3秒。刷新反馈显示实时采集/缓存及耗时信息。失败结果也在窗口内复用，仍明确返回不可用，避免故障节点被重复请求；失败耗时不计入成功平均值。统计只在中心进程内保留，重启后重新积累。

选择 Runner 时仍强制核验实际状态（可合并同时进行的核验），不受普通刷新缓存窗口限制；提交任务仍由中心占用记录和远端 Runner 执行锁校验。缓存中的空闲状态不是资源分配凭据。

中心重启后用户任务归属保留到会话过期，但旧的选择和刷新状态失效，需要重新选择。浏览器 Cookie 清除或匿名会话过期后，旧任务需要管理员接管。网络结果未知时，不按TTL盲目释放占用。

任务退出后自动核对进程组，已退出但尚未回收的僵尸进程不计为运行中的测试。确认无活跃子进程后，Runner 和中心自动释放占用。若清理暂未确认，下次状态查询会再次核对并自动恢复；忙碌状态点击刷新不会复用旧忙碌缓存。仍有活跃进程或无法读取进程信息时继续保留占用。

旧版本已卡住的成功任务可在升级迁移时使用管理员卡片的“恢复已结束任务”：重新连接 SSH 后，工具核验成功结果、原请求和进程组，备份记录与源码，更新并重启已核实的本项目 Runner，确认新实例空闲后才释放中心占用。这个入口用于旧版本迁移，更新后的正常任务无需管理员操作。

## 外网、内网与离线安装

分开看两段网络：中心电脑安装 SSH 组件，服务器容器安装 AISBench。

外网可达时直接运行安装器。内网电脑可以在有网环境下载 ZIP 再拷贝，首次 pip 按实际环境设置代理或源：

```powershell
$env:HTTPS_PROXY = 'http://代理地址:端口'
$env:PIP_INDEX_URL = 'https://可达的pip源/simple'
.\setup-shared-center.cmd
```

HTTP 内网 pip 源还需设置 `PIP_TRUSTED_HOST` 为明确可信的源域名，优先HTTPS。企业CA可用 `PIP_CERT`，不需要关闭TLS验证。电脑代理不会自动成为服务器可达的代理。

完全离线时，在与中心电脑同系统、架构和Python版本的联网环境准备 wheels：

```bash
python -m pip download -r requirements-admin.txt -d wheelhouse-admin
# 拷贝工具与wheels至离线电脑后：
python -m pip install --no-index --find-links wheelhouse-admin --target .fleet-deps -r requirements-admin.txt
```

不要跨 Windows/Linux、CPU架构或Python ABI复制虚拟环境。

服务器侧在网页“安装网络”填写服务器可达的代理、pip源和可选域名映射，沿用原版安装能力。不接受地址中嵌入的账号密码或查询令牌。

HTTPS 包源默认使用中心操作系统信任的公共 CA 证书：部署时自动同步到 Runner 项目 `.pip-trust/`，只通过该次 pip 的 `PIP_CERT` 使用，不关闭 HTTPS 校验、不修改宿主系统信任库。可选“包源可信 CA”路径优先于自动同步，路径须在容器可读的 `/mnt` 或 `/home` 中。中心系统也不信任的企业 CA 仍需管理员提供可信证书，不能通过关闭校验绕过。

| 字段 | 示例，按实际替换 |
|---|---|
| 服务器代理 | `http://proxy.example:3128` |
| pip源 | `https://mirror.example/simple` |
| 可选域名映射 | `192.0.2.20 mirror.example` |

只有明确填写映射时才修改所选容器 `/etc/hosts`，不改宿主机 hosts。工具包由中心 SSH 上传，服务器无需访问GitHub。完全离线的服务器必须已有可执行 AISBench 或匹配的离线依赖；源码包不捆绑所有wheels、镜像和模型。
