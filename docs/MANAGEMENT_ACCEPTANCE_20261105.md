# 自动 SSH 管理与网络恢复验收（2026-11-05）

本轮按要求优先完成首次授权后自动重连、自启动代码与连接压测。使用隔离中心、工具专用授权和专用测试容器；没有重启共享服务器，没有操作其他人的容器或 vLLM，没有发送额外模型请求。

## 行为

- 首次核对服务器指纹并输入密码，登记工具专用 SSH 公钥和独立签名公钥。密码不保存；后续管理使用工具密钥。
- 私钥通过 Windows 机器 DPAPI 加密，目录 ACL 限于当前用户和 SYSTEM；不读取个人 SSH 配置、私钥或 ssh-agent。
- SSH 授权限定来源 IP、强制命令、禁止转发；只运行通过签名和一次性挑战校验的管理脚本。部署脚本仍具有服务器授权用户的管理权限，中心电脑必须受保护。
- 断线退避自动重连，重试间隔 2–60 秒；认证被撤销或主机指纹变化时阻止重试并明确报错。不会重复提交已发送但结果未知的部署命令。
- 中心重启加载已加密凭据。服务器安装本工具独立 systemd 服务，验证容器 ID、程序哈希和端口身份后恢复登记的 Runner/TLS 进程；不抢占未知端口，不启动或停止 vLLM。
- 新建工具容器设置 `unless-stopped`。外部停止容器等待所有者启动，不能把本功能理解成自动开启共享服务器的全部容器。
- 可在管理员界面撤销自动管理；已打开 SSH 会话也不能继续执行。

## 实机结果

| 用例 | 结果 |
|---|---|
| 两台服务器首次真实密码授权 | 通过，后续未再输入密码 |
| 独立中心进程重启、恢复专用密钥连接 | 通过 |
| 8 条真实 SSH 连接、10 分钟采样、4 轮各 4 秒人为断线 | 全部恢复 |
| 已派发写入操作回包中断后重连 | 只执行一次，无自动重放 |
| 专用 Runner 进程退出后恢复 | 通过，新实例空闲 |
| 专用 TLS 进程退出后恢复 | 通过 |
| 专用容器重启后恢复 Runner/TLS | 通过 |
| 专用 systemd 服务重启且开机启用 | 通过 |
| 未签名请求、SSH 转发 | 被拒绝 |
| 撤销授权后的既有会话、新连接 | 均被拒绝 |
| 清理 | 只删除带本次标签和已核对 ID 的测试容器，撤销两项测试授权及其 systemd 服务；结果文件保留 |

压测共成功完成 **1351 次**管理命令，成功请求中位耗时 **2.157 秒**，P95 **2.781 秒**。每轮网络恢复至各连接首次成功请求为 **2.313–41.188 秒**；末尾 8 条连接均再次验证成功。采样窗口 600 秒，包含收尾核验的总耗时 620.83 秒。故障期间有 320 次不可用操作记录，包含退避期调用，不是独立 SSH 认证失败次数；全部没有请求管理员重新输入密码。此结果证明本次有限故障注入可以恢复，不代表已完成数天连续运行验证。

本地 Python 回归 **90 项通过**，前端 Runner 选择回归通过，JavaScript 语法检查通过。

初次服务器恢复服务测试遇到交互式 Conda Python 启动问题，改为清洁环境下 `/usr/bin/python3 -I -S` 后通过。专用恢复测试脚本曾出现变量引用错误，修正后重新完成全部恢复用例，原始结果保留失败记录。

## Windows 开机中心的实际边界

提供 `install-center-autostart.cmd`：复制程序、完整 Python 与中心数据到受保护的 ProgramData 目录，再注册 SYSTEM 开机任务，不依赖用户登录，也不保存 Windows 密码。

已验证开机任务 XML、目录/身份归属检查及无管理员权限时在修改前拒绝的逻辑；当前测试进程没有 Windows 管理员权限，实际运行安装器亦被这一检查拒绝，**没有实装 SYSTEM 开机任务，也没有实测 Windows 重启后启动**。服务器恢复链通过专用容器和专用 systemd 重启验证，未重启共享宿主机。

启用步骤：正常停止当前中心，右键以管理员身份运行 `install-center-autostart.cmd`；之后使用 ProgramData 中的中心数据。已有服务器在管理页选择“重新登录/授权”，勾选自动管理，分别授权一次。发布 ZIP 不含本机凭据，不能通过下载 ZIP 自动获得服务器权限。

原始 `results.json` 位于本次工作目录 `outputs/network-verify-20261105`；私有测试中心数据库、加密私钥、TLS 令牌不进入发布包或公开验收附件。
