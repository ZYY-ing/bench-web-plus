# 中心首次部署、重新配置与排障

> 当前操作总入口见[README](../README.md)，实现与验证边界见[当前交接](HANDOFF.md)，其他文档见[索引](README.md)。


适用于当前 main 源码。示例地址和路径必须改成实际值；不包含实际机器凭据。

## 新电脑推荐顺序

1. 只有选定的中心电脑安装Python 3.12+（包含pip）与工具包；其他管理员和用户只需要浏览器。团队通常保留一个有效中心，不在每个管理员电脑重复安装。
2. 从当前 main 下载完整源码 ZIP，或使用当前源码构建的完整分发包，解压到本人可写的新目录。完整Python官网下载安装和PATH说明见 [共享中心部署说明](SHARED_CENTER.md)。
3. 双击 setup-shared-center.cmd。填写固定HTTPS网址、实际用户网段、首个管理员账号和密码；选择公司证书或生成测试证书。密码输入不显示字符或星号，输入后按回车，长度12–256字符。
4. 安装器创建当前Windows用户登录后运行的任务。确认任务运行、中心端口监听；管理员网页可关闭，但中心电脑仍需登录Windows、联网且不休眠。
5. 由有权限者按实际用户网段放行中心TCP端口。测试证书需在访问电脑信任 .fleet-data/tls/ca.pem；不跳过浏览器安全警告，不分发私钥或整个数据目录。
6. 用另一台电脑实际打开中心网址，确认免登录用户页可用；管理员登录接入服务器，随后退出管理员再验证用户刷新。
7. 新中心从空清单开始，不自动获取原电脑账号或服务器权限。重新经SSH核验并接入已有Runner；同一批Runner的测试使用一个中心，多个独立中心不共享中心侧占用记录。

## 常见问题

| 现象 | 原因和处理 |
|---|---|
| 双击后只剩 Press any key to continue | Python可能是Windows商店占位入口。安装真实Python，勾选 Add python.exe to PATH，关闭旧窗口后重开，验证 python --version 和 python -m pip --version。新版启动器会明确报缺少解释器。 |
| PowerShell不认识 py | py启动器没有加入当前进程PATH；新开终端或用python.exe完整路径。使用下方FLEET_PYTHON方式，不必重复安装工具。 |
| 两次密码不一致 | 新版会原地重试。确认键盘布局、大小写及输入法，两次输入同一密码；不要把密码发到日志、命令参数或聊天。 |
| 重新打开安装器仍用旧账号 | 已有账号会保留。改密码运行 fleet.admin reset 账号名；重设密码不是重新部署中心。 |
| 任务已创建，随后报XML编码错误 | 旧预览对schtasks管道编码处理有误。使用本版本 fleet/service.py，并在原安装目录运行 fleet.service start；不用重建账号/证书。 |
| 同名任务归属检查拒绝 | 新版会解析Windows账号到SID。如果仍拒绝，应核对任务是否属于另一个用户或安装目录，不应删掉未知任务或绕过检查。 |
| Python 3.14报 Missing Authority Key Identifier | 旧测试证书缺少严格TLS字段。本版本新生成证书已修复；仅替换代码不自动改已有CA。首次部署可按下方备份重新初始化，再信任新的ca.pem。已有团队中心应安排证书迁移，不能关闭验证。 |
| 网页本机可打开，其他电脑打不开 | 检查填写的是中心可达IP而非127.0.0.1、端口监听、防火墙、实际客户端源IP是否在允许网段、证书是否可信，以及Wi-Fi/VPN是否隔离客户端。中心能连服务器不等于用户能连中心。 |
| 安装目录缺少持久化RW挂载 | 所填容器内目录不属于该容器的可写持久挂载。按下节核对现有挂载，不重建其他人的容器、不关闭保护。 |
| 日志有 Runner HTTP 200，但安装提示未就绪 | 先用容器内 `curl --noproxy '*'` 检查回环端口；旧安装脚本和状态查询可能受容器代理影响。新版回环健康检查明确绕过代理，安装时最多等待30秒启动窗口。失败后新建的容器已存在，重试选“使用已有容器”，沿用原目录和端口，不重复创建。 |

已安装但命令找不到Python时，在PowerShell中使用实际路径（下面是占位示例）：

```powershell
$env:FLEET_PYTHON = 'C:\Path\To\Python\python.exe'
& $env:FLEET_PYTHON --version
& $env:FLEET_PYTHON -m pip --version
.\setup-shared-center.cmd
```

该环境变量只在当前终端有效；后台任务会记录实际解释器路径，无需全局设置。

## 地址、网段和端口怎么填

中心网址示例 https://192.0.2.10:19885，冒号使用英文字符。IP必须属于中心电脑，其他用户电脑到该地址实际可达，端口未被其他服务使用。DHCP地址变化需要固定租约或重新配置地址及证书。

允许网段是访问用户电脑的实际来源网段，不是服务器网段，也不是随意填写的范围。192.0.2.0/24 表示该子网；192.0.2.80/32 仅允许单个IPv4地址。多个网段用英文逗号分隔，不允许0.0.0.0/0。中心允许范围和防火墙范围应一致；有VPN/NAT时按中心实际收到的源IP判断。

| 示例端口 | 所在位置 | 作用 |
|---|---|---|
| 19885 | 中心电脑 | 管理员/用户浏览器访问的HTTPS网页 |
| 22 | 服务器 | 部署和维护使用的SSH |
| 19787 | 服务器宿主机 | 中心日常访问的受限TLS连接组件；需要凭据，不是个人电脑的SSH隧道端口 |
| 18787 | Runner所在服务器/host容器 | Runner自身回环接口，由连接组件内部访问 |
| 8000 | 模型服务所在机器 | 已有vLLM接口示例，与上述端口独立 |

用户日常只访问中心网址。不同服务器可用相同连接端口；同一服务器接入多个Runner应使用分别未占用的Runner端口与连接端口。未知占用不会自动抢占或换端口。

防火墙示例仅供有权限者在确认实际地址后执行；不要直接照抄示例IP，不要关闭防火墙：

```powershell
New-NetFirewallRule -DisplayName 'BenchWebPlus HTTPS 19885' -Direction Inbound -Action Allow -Protocol TCP -LocalAddress 192.0.2.10 -LocalPort 19885 -RemoteAddress 192.0.2.0/24 -Profile Any
```

## 已有容器安装目录报错

若 `ais_bench` 文件存在但启动报 `[Errno 2] No such file or directory`，还需检查文件首行的 Python 解释器。共享目录中的旧虚拟环境可能指向上一容器才有的 Python。当前部署会实际运行 AISBench 检查可用性；失效的虚拟环境先备份再按当前容器重建，保留任务结果。不要仅用 `ls` 或可执行位判断已安装成功。

请求超时默认选择“使用 AISBench 原生配置（不限时）”：当前配套 AISBench 的 `REQUEST_TIME_OUT = None`，不再默认附加 600 秒限制。选择“自定义超时时间”后，填写每次 HTTP 请求的总时限（1–86400 秒），同时作用于预热和正式推理的共享 HTTP 会话；重试的每次尝试分别计时。导出的 `timeout: null` 表示原生模式，数字表示自定义秒数；已有任务保留提交时的配置。升级时从当前 Runner 的脚本目录加载补丁，复用旧 AISBench 环境也会生效。

在服务器只读核对所选容器：

```bash
docker inspect <容器名> --format '{{json .Mounts}}'
```

Destination 是容器内路径，Source 是宿主机路径，RW 必须为 true。Runner安装目录应为一个可写挂载的专用子目录；开启持久连接时，还须能确认它对应的宿主路径。例如已有 Source=/home/your-user/aisbench_web、Destination=/work/bench、RW=true，则容器内安装目录可用 /work/bench，不能把宿主路径误填为容器路径。

界面示例 /home/ascend_bench/runner 不保证存在于每个已有容器挂载中，安装包缓存目录也必须改为自己有权限使用的共享盘专用目录。安装包上传成功不代表Runner安装成功；持久挂载检查失败时安装流程会停止。

## 改密码、重配网络、从头部署

以下命令均在中心安装目录执行。能使用python时执行python -m；否则使用 & $env:FLEET_PYTHON -m，先按上文设置真实解释器路径。

仅重设已有管理员密码：

```powershell
& $env:FLEET_PYTHON -m fleet.admin reset admin
```

向导交互输入两次新密码，不需要删除配置或重装服务。旧登录会失效。

重新配置网址/网段前，先执行 fleet.service stop 停止当前中心，再次运行 setup-shared-center.cmd，会保留已有账号。测试证书会重新签发服务证书；跨电脑访问仍需检查证书和网络。不要在旧进程仍运行时把安装器的启动提示当作新配置已生效。

真正从空白重新部署中心：

```powershell
& $env:FLEET_PYTHON -m fleet.service stop
& $env:FLEET_PYTHON -m fleet.service remove
```

确认两条命令成功后再备份数据目录：

```powershell
Rename-Item -LiteralPath '.fleet-data' -NewName ('.fleet-data.backup-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
.\setup-shared-center.cmd
```

不要盲删其他目录或未知后台任务。备份含账号校验值、接入凭据和私钥，只留在受保护位置，不上传。重置中心不会停止或删除服务器容器、Runner、连接组件或结果；旧服务器接入应由管理员核对后重新登记。新的中心CA需要重新信任；也不要把旧电脑整个 .fleet-data 发给其他用户。
## 容器 Python、ensurepip 与线程兼容

安装时需要验证所选 Python、venv/ensurepip 和实际 AISBench 启动能力，不能仅凭路径存在判断可用。换容器后依赖环境按完整容器 ID 隔离；不复用另一个容器失效的解释器链接。老 Docker 的 clone3/seccomp 限制由进程级兼容处理，不要求 privileged 或关闭 seccomp。仍有段错误时保留日志和底层异常，停止安装，不修改他人的模型环境。

## 持久 SSH 部署在“检查共享路径安装包缓存”时中断

2026-11-07 修复：离线 OpenCV、NLTK、joblib wheel 使 Runner 包由约 7.31 MB 增至 38.52 MB。旧持久管理上传将整个包先编码到脚本，再把脚本编码为签名请求，生成约 68.5 MB 请求，超过远端管理通道原有的 32 MiB 请求 / 24 MiB 脚本限制，连缓存检查都无法执行。

中心现在先用小请求查询完整 SHA256；命中上传 0 B，缺失时每块最多 1 MiB 传入独立临时文件，校验块哈希、偏移和整包 SHA256 后原子发布。远端安全限制保持不变，传输结果未知时不自动重放安装命令。此修复在中心生效，不需升级或重启模型服务、Runner 或远端授权代理。

## 请求连接已断开，但进度长期停在最后一条

2026-11-07 在 aiohttp 3.14.5 上确认：HTTP chunk 解析失败（如 `Expected LF after chunk data`）关闭连接后，正在等待的 response payload 可能既没有 EOF，也没有收到异常，导致 AISBench 的 `asyncio.gather()` 一直等待。评测子进程通过 `aisbench_runtime.patch_http_disconnect` 将协议层异常交给同一响应的读取器，之后由 AISBench 原生 `generate()` 捕获、重试及记录失败。连接关闭时仅对未完成且没有异常的 payload 补充断连异常；已完成响应不变。没有新增超时、重试次数转换或额外重试，`REQUEST_TIME_OUT=None` 保持不限时。

该兼容处理仅在新启动的 AISBench 任务进程中加载，更新模块不重启 Runner，不热修改既有任务，也不修改模型服务环境。更新前已经卡住的进程不会自动获得补丁。隔离测试使用本机临时模拟 HTTP 服务，覆盖原生流式/非流式重试成功、重试耗尽、连接中断、正常响应、不限时慢响应和自定义超时；不向 vLLM 发送验证流量。

## 精度任务退出码为 0，但评分为 `-`

空 summary 表不表示评分成功。若前面有 `Inconsistency detected by ld.so`、`dl-tls.c`、`Fatal Python error`，说明推理或评分子进程已崩溃；若有 warmup 全失败或 `No predictions found`，应先修复请求失败。

自 2026-11-07 起，运行完成状态遵循 AISBench 原生退出码。Runner 保留失败请求数量、预热摘要和缺失结果提示，不再用这些后处理条件覆盖原生退出结果；“已完成”不等于每条请求都成功。性能输入或定长输出与配置目标不一致时，在网页及导出记录中提示目标值和原生统计值，不改写原始 CSV、JSON 或指标，也不因此判失败。

HTTP Runner 的评测进程启用 `ASCEND_BENCH_API_ONLY=1`，在进程内禁用不需要的 `torch_npu` 可选后端，防止 MMEngine 显式导入它并初始化 NPU。仅设置 `TORCH_DEVICE_BACKEND_AUTOLOAD=0` 无法阻止 MMEngine 的直接导入。安装预检会加载实际 AISBench 依赖并创建线程；不修改服务端 vLLM、NPU 驱动或全局 Python 包。

当前参数规则、tokenizer 可见性与验证范围见[交接文档](HANDOFF.md)。

## 大型性能数据集生成超过 30 秒

128k 输入、90% 共享前缀的 2560 条数据约为 1.34 GB，首次生成与分词校验需要数分钟。旧中心的受限连接约 30 秒结束等待，但 Runner 仍在后台生成。

中心现仅对 `/api/datasets/generate` 保存同一份请求参数，在读取结果超时后继续确认缓存。Runner 的生成锁阻止重复并行生成，完成后校验参数对应的缓存并返回。初次就遇到忙碌仍立即提示；参数错误、认证和证书错误不做自动重试。测试任务提交及部署命令不套用这一逻辑。

确认等待有 30 分钟预算；超过预算会明确说明后台生成未被取消，可用完全相同的参数稍后确认。不要为了等待生成而停止 Runner 或重复部署。实测范围见[交接文档](HANDOFF.md#验证证据与不能宣称的事项)。

## 多用户生成、测试和共享缓存互锁（2026-11-07）

- 同一 Runner 的服务检查、配置修改、数据准备、数据生成和测试互斥。连接检查从开始探测到保存配置一直持有预留，测试从前置检查开始预留；旧请求会在取得预留后再次核对连接身份。
- 同一个中心内，测试按 Runner 和规范化后的目标服务地址占用；冲突提示包含占用 Runner 地址和目标服务地址。不同用户、不同标签页共用后台锁，不依赖按钮禁用。
- tokenizer 只读不加互斥锁；不同 Runner 可以同时读取同一分词器。14、22 默认缓存分别在各自本地 ext4 的 `/home/ascend_bench/runner/datasets/perf`，并非共用目录。
- 若显式共用缓存目录，校验和生成使用本机线程/进程锁，加跨机器的原子硬链接占位。已实测 `/mnt/share` 的 NFS 挂载为 `nolock/local_lock=all`，不能单独依赖 `flock` 或 `lockf`。不同缓存目录仍可并行。
- 缓存占位只由所有者正常释放，或由父 Runner 在确认确切生成子进程退出后清理；不按超时强抢。若整机/容器异常失联而退出尚无法确认，保留占位并明确报忙，不能猜测空闲后删除他人的锁。
- 同一浏览器已确认选择过的 Runner 分别保留访问资格，选择另一个 Runner 不撤销原标签页的查询资格；未选择过的 Runner 仍不能提交操作。

验证覆盖独立 HTTP Runner、多用户/多标签页、同服务跨 Runner 抢占、失败释放、连接检查竞态、进程异常退出，以及 14、22 共享盘跨机器写入排他；测试不向现有 vLLM 发起推理请求。

## Runner 显示空闲，但提交提示目标服务已占用（2026-11-09 修复）

旧版 Runner 重启后可能把旧任务标成 interrupted，并直接上报 idle；中心没有收到可信结束凭据，仍保留 Runner 和目标服务占用。新版列表合并中心占用状态，此时显示“占用待自动核对”，不作为空闲 Runner 放行。

Runner 自动检查旧进程组及带任务标记的后代，僵尸不算活跃；重启或 PID 重用通过启动身份区分。确认全部退出后保留“已中断”或已知原始结果，写入退出凭据，中心每5秒的后台核对自动释放对应占用，无需管理员点恢复按钮。暂时断网或进程状态不可读时继续保留并自动重试，不停止旧任务、不改 vLLM，也不按超时时长直接清锁。

## 管理员手动清理（2026-11-07）

管理员页「清理」扫描所有已登记 Runner。天数可填写（默认7天，1–3650整数），列表显示 IP、容器、名称、完整路径、占用与最近时间。扫描完成默认全选，可取消部分项目，再点击「清理所选」。没有定时任务，不自动删除。

范围仅限安装目录下 `datasets/perf/<缓存目录>` 和 `results/jobs/real-<任务编号>`。缓存以最近生成/复用或文件更新时间计算；任务以结束时间及结果最后更新时间中较新者计算。没有结束证明、正在生成/测试、占用未知的目录不删。任务整个目录删除后，其 `record.json` 一并删除，测试记录列表下次读取不再显示；不保留任务摘要。

只有管理员会话和 CSRF 校验可访问中心清理 API。实际操作经已授权管理 SSH 调用，用户评测网关不开放清理接口。删除前再次核对签名清单、时间、目录身份、文件变化和占用；扫描清单1小时有效。共享缓存使用现有跨机器写锁，并保留很小的锁文件及所在目录，避免删除锁 inode 导致并发写入失去互斥。性能任务持有缓存读取标记，确认任务进程退出后释放；未知标记不按时间强拆。

清理不涉及模型权重、tokenizer、精度数据集、依赖环境、凭据、容器或 vLLM 服务。连接失败时不自动重试删除；重新扫描核对。缓存删除后下次使用重新生成。
