# Runner 替换、并存与 66 环境核查（2026-11-05）

本文件记录先前自动停止旧 Runner 的版本。按用户后续要求，已撤下自动释放选项，现要求管理员手动停止/删除旧容器后再复用，回退只恢复文件、不自动启动旧容器。最新操作以 SHARED_CENTER.md 和 RUNNER_MANUAL_STOP_20261105.md 为准。

## 管理员操作

| 模式 | 操作 | 结果 |
|---|---|---|
| 一台机器保持一个 Runner | 勾选“释放并替换旧 Runner”，选择旧条目，再选新容器 | 自动带入旧端口、项目目录、挂载目录和受限连接端口；仅停止已核验且空闲的旧 Runner 进程，成功后原条目切换到新容器 |
| 同机多个容器 Runner | 不勾选释放，选择新容器 | 自动建议独立端口和项目目录，保留旧条目并新增一项；同时检查真实宿主机挂载，防止路径别名复用同一份文件 |

原容器和 vLLM 不停止，历史结果与旧依赖文件保留。释放的是 Runner 进程及监听端口，不是删除容器、依赖或归档结果。忙碌或未知身份的旧进程不释放，未知端口不抢占。旧容器已经停止或删除时不会强行启动它。

同机多 Runner 可以评测不同机器的推理服务。它们共享宿主 CPU、内存和网络，不构成性能隔离；同一中心仍禁止多个任务同时占用同一个目标推理服务。

## 防止更换容器破坏原环境

新虚拟环境位于 `environments/<完整容器ID>/bench-venv`，可编辑 AISBench 源码位于相同 ID 下的 `benchmark`。不再通过改名、重建共享 `bench-venv` 修复另一容器；也不复用其他容器 ID 的项目虚拟环境。

复用前实际执行 AISBench `--help`，检查启动解释器。允许复用新容器内实际可执行的系统 AISBench；旧配置的失效路径不会仅因 Runner 源码最新而被跳过修复。容器更换时同步磁盘配置，避免状态接口和持久恢复服务使用不同容器身份。

替换前核对原 Runner 空闲、容器、目录、启动环境及监听 socket；备份程序和配置，暂停匹配的本工具恢复记录，再释放进程端口。安装阶段抛错时，恢复原程序和配置，并重新启动原先运行中的 Runner。新容器独立的未完成依赖不会覆盖旧环境。

TLS 接入在 Runner 健康后迁移，中心内自动重试。若该阶段持续失败，保留已就绪的新 Runner 并标记接入待恢复，不把失败显示为完成；这与安装阶段的程序回退是不同阶段。断电或强杀安装进程不等同于可捕获的安装异常，不能据此承诺所有基础设施故障均已验证自动回退。

## 其他电脑与中心升级

其他个人电脑浏览器访问同一个中心网址，在允许网段中登录管理员，使用同一份 Runner 清单和 SSH 授权。SSH 从中心电脑发起，专用密钥留在中心；浏览器电脑不用配置 SSH 或重复输入服务器密码。独立部署另一套中心不等于访问同一中心，不能自动继承机器 DPAPI 凭据。

运行中的开机中心位于受保护的 ProgramData 目录；工作区改代码不会自动更新它。需一次管理员 PowerShell 更新（升级保留受保护中心的实时账号、数据库、档案和授权）：

```powershell
cd D:\aisbench_web\bench-web-plus
& 'C:\Users\example-user\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -X utf8 -m fleet.service stop --boot
& 'C:\Users\example-user\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -X utf8 -m fleet.service install-boot
```

当前代理进程没有 Windows 管理员权限，未更新受保护副本，也未停止当前中心。
