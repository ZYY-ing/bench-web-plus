## 已实现的修改

- `pressure` 只决定是否传 `--pressure --pressure-time N`。`steady_state` 单独决定配置 `StablePerfMetricCalculator`；关闭时明确使用 `DefaultPerfMetricCalculator`，四种组合独立。
- 共享内存适配仅在本工具的 AISBench 子进程启用。大分配使用任务独有的磁盘 mmap 文件，保留原生调度、推理、预热和统计；小分配仍走原生共享内存。
- 生成/校验性能数据在独立 CPU 子进程执行。生成 API 迅速返回 202，网页用同一请求标识轮询阶段及数量；重复轮询不启动第二个生成器，不同规格仍被 Runner 占用锁阻止。新一轮手动生成有独立标识，可重新验证缓存或重试失败。
- 网页生成期间保留当前选择并锁定配置，避免窗口 focus 事件把正常的 preparing 状态当作断线；列表明确显示“数据准备中 · 连接正常”。结束或失败自动释放占用。
- 额外参数列表移除温度、并发、输出长度、预热、超时、重试、流式、pressure 等已在表单中的重复项；重复填写会明确指出对应表单。
- 其他服务生成参数支持 `generation_kwargs.参数名=JSON值`，直接进入 AISBench 模型配置，再由原生 API 实现发送；服务端负责验证其支持范围。补充 `enable_ssl`、`verbose`、`meta_template`、`api_key` 和 `max_workers_per_gpu` 的配置/命令透传。
- 不宣称支持 AISBench 的全部 CLI 场景：任意模型/数据集 Python 配置、`--models`/`--datasets` 切换、自定义评分器等不属于当前网页已接入的三个精度数据集与合成性能数据流程，不能当作任意 shell 参数注入。未接入的顶层参数明确拒绝。模型/生成参数写入 `config.py`，CLI 项写入实际命令，而非把所有参数拼成 CLI。
- 更新脚本逐项校验开机恢复记录对应的实际文件，修正网站文件的路径映射；不强行释放部署锁，不中断忙碌任务。
